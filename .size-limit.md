# Bundle budgets

`.size-limit.json` is the enforced version of ENGINEERING.md §11.

The budget is on **installed bytes**, not repository size: a component library's
value proposition is what a customer ships to their users, and everything else
is our problem rather than theirs.

Limits sit just above today's measured size so they **ratchet rather than
aspire**. When a number here goes up, that is a decision someone made in a pull
request — which is the point. Lower them when you can; never raise one to make
a build pass.

React and react-dom are excluded from the React measurements because they are
peer dependencies the host already has.

## Timeline's 8 kB is mostly `cn`

`Timeline` measures 7.17 kB and roughly six of those are **tailwind-merge**,
reached through `cn` in `registry/zoblocks/lib/utils.ts` — the same finding as the
accordion, below, and for the same reason: the component uses no Tailwind
utilities of its own, so `twMerge` is resolving conflicts between classes that
are never emitted. The component itself is an ordered list with a rail and is
about a kilobyte.

Not fixed here for the reason given in the accordion note: `cn` is the house
convention and diverging in one component is how a convention rots. It is worth
saying plainly that both numbers are really one number, measured twice.

## The theme barrel's 21 kB was never a measurement

Raised to 27 kB, and this is the one raise in this file that is not a ratchet
being let out — it is a number being measured for the first time.

21 kB was written in the same commit that added `packages/theme/src/logo.ts`,
which imports `node:crypto`. `logo.ts` was re-exported from the barrel, so
`size-limit` could not bundle the entry at all: every run since has failed with
`Could not resolve "node:crypto"` before reaching a single budget. The figure
was an estimate nobody could have checked, and nobody did.

With the checker moved behind `@zoblocks/theme/logo` — where it belongs,
since it hashes uploaded bytes — the entry bundles, and it measures 26.57 kB.
Two inputs are almost all of it:

- **`packages/tokens/src/surface.ts`, 52 kB minified.** The 282-entry token
  surface. `emit.ts` walks it to write the stylesheet and `validate.ts` looks
  entries up to judge a theme; both are the barrel's actual job, and ADR 0012
  makes that manifest a contract rather than a detail. It is not fat.
- **zod, roughly 60 kB minified.** The document schema, which is what turns a
  payload a customer typed into something the gate can refuse.

So the honest reading is that this entry measures a validator and a schema, and
27 kB is what those cost. The lesson is not about the number: **a budget written
beside a change that stops the tool running is not a budget.** `pnpm size` and
`pnpm deps` are two of the eight gates CI runs, and they were the two that went
unrun.

**Now 28 kB.** It measures 27.19 kB — 188 B over the 27, which is the ratchet
doing its job rather than anything going wrong: six commits have touched
`packages/theme` since the number was set, and none of them is a regression.
This one was red on `main` alongside the barrel and is the reason `pnpm size`
failed twice.

One thing found while measuring it, recorded because it is a real finding and
not a budget question: **React is inside this entry.** `packages/theme/src/index.ts`
says in its own header that the React provider lives at
`@zoblocks/theme/react` "so a server that…" — but `react` is reached
anyway, through `packages/bridge-core/src/useZoBlocksTokens.ts`, and this entry
has no `ignore` list to exclude it. The server-safe entry is not React-free.
Fixing that means moving the hook, not moving a number, so it is not done here.

## The barrel is at 110 kB, because 46 kB was measuring a smaller library

Raised from 46 kB, which measured 106.16 kB against it — 58 kB over, and red on
`main` rather than on any one branch.

This is the raise that most looks like the thing this file forbids, so here is
the evidence it is not. 46 kB was last fitted at `23573cf`, when `registry.json`
held **21 items**. It holds **48** today. The catalog more than doubled and the
number never moved, so what failed is the budget's age, not the bytes. The
date-range, time-range and pixel work that happened to be in flight when it went
red moved the barrel by **30 bytes** — measured by stashing it and re-measuring
on a clean tree.

Two things were checked before the number was touched, because either would have
been a better fix than raising it:

- **The barrel still tree-shakes.** This was worth checking properly: the
  per-component entries all point at a component's own subpath, so none of them
  actually tests the barrel. Importing one export _through_ `dist/index.js`
  costs what importing its own file costs — `Switch` 11.95 kB against 11.92 kB,
  `Accordion` 9.82 against 9.83, `PulseLoader` 7.82 against 7.81, `Timeline`
  7.42 against 7.39. A consumer who imports one component still ships one
  component.
- **No UI framework is in it.** Bundling the barrel and reading the metafile:
  **0 of 109 input modules** come from `antd`, `@mui`, `@ant-design` or
  `@emotion`, and only two come from `node_modules` at all — `clsx`, and
  `tailwind-merge` at 5.84 kB brotlied of the total. The other ~100 kB is the
  catalog's own code, about 2 kB per component. `ClinicalNote` is not in here:
  ProseMirror stays behind the `./clinical-note` subpath, which is why that
  entry is 75 kB and this one is not.

So the number still guards the two things worth guarding — **that no UI
framework is in the barrel, and that the whole-library bundle does not jump
suddenly** — and it guards them from a measurement taken today rather than from
one taken at twenty-one components.

What it still is not is a budget on what anyone ships. The barrel imports every
component, so its size is the catalog's size and it grows every time the catalog
does; a consumer importing one component gets the per-component entry, which is
why those exist. The open proposal is still to split it per layer or drop it in
favour of the per-component entries. Until that is decided, the number is kept
so a _jump_ is still visible, and raised deliberately rather than quietly.

## The barrel's two entries stop sharing a number (2 Sep 2026)

The 360 bytes of headroom recorded below lasted two commits. DataGrid gained a
selection model, pinned columns and an end-of-list sentinel, went 9.4 → 10.5 kB,
and the barrel went to 110.78 against 110.

The note below told whoever hit this to split the entry rather than add two more
kilobytes. **The split is not available today**: `@zoblocks/react` has one
`dist/index.js` and no per-layer entry points, so there is nothing to give a
per-layer budget to. Making them is a package change with its own argument, and
doing it inside a component change would bury it.

So the two entries stop sharing a number instead, which is the part of the fix
that _is_ available and is arguably what should have happened at 46 kB:

- **`react — the barrel must contain no UI framework` → 200 kB.** Its job is
  catching antd or MUI arriving in a package that does not declare them. antd
  alone is several hundred kilobytes minified; a 200 kB ceiling catches that and
  nothing else. Sharing the growth number meant this guard failed every time the
  catalogue grew, which taught everyone to raise it without reading it — the
  exact way a guard stops guarding.
- **`react — the whole barrel` → 113 kB.** The growth tracker, at the measured
  110.78 plus headroom, still doing the one thing it can honestly do: make a
  _jump_ visible.

That is two raises in three days on this entry, and the pair of them is the
evidence. Per-layer entry points are now the open item, not the proposal.

## What DataGrid's 10.5 kB buys

The engine and the surface. Coverage arithmetic with an `"unknown"` total, a
cell value type with no null member and its five absence reasons, comparison
that holds absence at the bottom in both directions, two-dimensional cursor
arithmetic for `role="grid"`, the footnote collector, the capacity refusal, a
delimited writer that neutralises formula injection, and — as of the enterprise
worklist pass — a selection model, measured pinned-column offsets, an empty
state, and an intersection-driven end of the list that stays honest when the
server withheld a total. A pager was built first and removed: against a
conformant FHIR search there is no addressable page four to jump to. It sits between Timeline
(7.4 kB) and Switch (11.9 kB), which is about right for an organism carrying an
engine.

**Its contribution to the barrel is 3.19 kB** (106.45 → 109.64), not 9.4 — most of the component is
already in there through the shared engine, which is what a per-component entry
exists to show and what the barrel cannot. Measured by stripping the export from
the generated barrel and rebuilding, the way the 30-byte figure above was.

**The barrel now sits at 109.64 kB against 110, which is 360 bytes of headroom.**
Left alone deliberately: 110 was fitted one week ago with the evidence above, and
re-raising a number that still passes is the quiet ratchet this file exists to
prevent. But the next component will break it, and that is the point at which
the open proposal — split per layer, or drop it for the per-component entries —
stops being a proposal. Whoever hits it should do that rather than add two more
kilobytes.

The theme entry moved 27.19 → 27.32 kB with this component, well inside the 28
raised for its own reasons above. The 130 bytes are the eleven `--zb-grid-*`
tokens reaching `packages/tokens/src/surface.ts`, which that entry bundles —
what themeability costs, in a package a consumer's application never ships.

## What CareTimeline's 17 kB buys

Four layouts, eighteen declared states, two string catalogs, and the chronology
engine — precision-preserving time, the stable comparator, grouping, clustering
with the critical-promotion rule, the coverage claim and the sentence it
produces. It sits between Switch (13 kB) and Copilot (24 kB), which is about
where an organism of this size should.

Raised from 15 kB in the same session it was set, when the register split, the
jump control and the arrival live region landed — three features the brief
listed for v1 and the first pass had not built. The number moved because the
component grew, which is the only reason a budget here may move.

The engine is a third of it and is deliberately not a separate npm package yet.
`tabs-core` and `signature-core` earned theirs by having a second consumer — a
custom element, a testing package. This one has a single consumer today, and
shipping a package with one consumer is shipping a public API that has never
been tested against a second opinion. It lives in `registry/zoblocks/lib/`, shaped
so extraction is a file move rather than a redesign.

`Timeline` is budgeted separately at 6 kB precisely so that stays visible: it is
an ordered list with a rail, and if it ever grows past that number, something
clinical has leaked down a layer.

## What the accordion's number is actually made of

`react — accordion` measures 9.74 kB, and roughly six of those are
**tailwind-merge**, reached through `cn` in `registry/zoblocks/lib/utils.ts`.

The accordion uses no Tailwind utilities of its own — the header of
`accordion.css` states why, and the same is true of all five loaders. `twMerge`
therefore has nothing to merge: it is resolving conflicts between utility
classes that the component never emits. Plain `clsx` would produce identical
output for about a sixth of the bytes.

This is not fixed here, deliberately. `cn` is the house convention across the
whole catalog, and diverging in one component is how a convention rots — the
next author copies whichever neighbour they happened to open. It is a
catalog-wide change with a codemod behind it, or it is nothing.

Recorded rather than silently absorbed, because "why is a plain-CSS component
ten kilobytes" is the first question anyone reading this file will have.

`react — the headless behaviour layer` is the number to watch for the L1 claim:
**1.86 kB**, dependency-free, and it is where the accessibility correctness
lives. A customer who rebuilds the visuals keeps that and pays for nothing else.

## `react — copilot alone` moved 22 KB → 24 KB

Measured 22.95 KB after the design rework. The growth is the parts the mockups
called for and the first cut had skipped: the shared icon set, the panel's own
composer, the reasoning disclosure, the thread switcher, and the two-step
feedback picker. None of it is a dependency — the icons are hand-drawn SVG
precisely so a registry component copied into a customer's tree does not drag
an icon library behind it.

Still the number to watch, for the reason given above: the barrel is an
install-everything convenience, and this is what a customer who imports one
component actually ships.

## Copilot 24 → 29 KB and the barrel 113 → 117.5 KB (14 Sep 2026)

Copilot measured 28.72 KB, up from 23.29. The barrel measured 116.98 KB.

Most of it is the crisis classifier. The review found it missed "I want to kill
myself, no plan yet" because any negation cleared the whole message. The fix
masks negation and history per phrase and adds rules for overdose, attempts,
lethal means, passive death wish and recent past. `safety/crisis.ts` alone went
1.9 → 6.6 kB gzipped, measured by bundling it at `HEAD` and after. The rest is
per-exchange guards in `session.ts` and `pipeline.ts`.

A missed crisis is the one failure this component must not have, so the bytes
stay. If the number needs to come down, the route is loading the rule tables
lazily, not removing rules.

## The barrel 117.5 → 118.5 KB: the phone pass (25 Sep 2026)

The barrel measured 117.74 KB, 238 B over, and red on `main`. All of it is
`27b41d0` ("make the site and its components work on phones"): reverting that
commit's TypeScript in `packages/react/src` and rebuilding measures 117.01 KB,
which is the 116.98 recorded on 14 Sep plus noise. Nothing else moved it.

Reverting one file at a time puts the ~730 B where you would expect:

- **`lib/datetime-field.tsx`, ~410 B.** The date picker becomes a bottom sheet
  on a narrow or short-landscape touch screen (one month, scrim, scroll lock,
  faded preset rail), and the anchored popover is clamped inside the viewport,
  because at 375px it used to end 169px past the right edge. It also dismisses
  on `pointerdown` rather than `mousedown`, because iOS does not reliably send
  mouse events, and it follows the visual viewport when the keyboard opens.
- **`data-grid.tsx`, ~90 B.** The pinned identity column becomes the default and
  gets its scroll seam, and the checkboxes get a hit target big enough for a
  finger.
- The rest is spread across Switch, CareTimeline, Copilot and `timeline-core`.
  Reverting any one of those alone is within brotli noise.

No dead code was found to trim. Every part of it is a phone that used to fail
and now works. So the number moves, because this is a component growing, not a
regression. Per-component entries all passed unchanged (DataGrid 10.80 against
11, Switch 12.10 against 13), which is where a consumer's cost actually shows.

This is the third raise on this entry in a month. Per-layer entry points are
still the open item recorded above.

## The bridges, and the one number that is an assertion

Four packages arrived with the theme-bridge work, and three of their budgets are
ordinary ratchets. The fourth is doing something else.

**`react — the barrel must contain no UI framework`** deliberately does _not_
ignore `antd` or `@mui/material`. Every other React entry excludes peer
dependencies because the host already ships them; this one includes them so
that the number moves if one ever arrives.

It is the **second** line of defence, and worth being precise about which line
it is. Tested by adding `export { ConfigProvider } from "antd"` to the barrel:
the build fails first, with `Cannot find module 'antd'`, because
`@zoblocks/react` does not declare antd at all. A stray import therefore
cannot reach a release — the dependency graph stops it, not this budget.

What this entry catches is the case the graph cannot: somebody adding antd to
`packages/react/package.json` **on purpose**, at which point the import resolves,
the build passes, and the only thing left to object is the number. A framework
in this barrel would add hundreds of kilobytes against a 110 kB limit, so the
objection is immediate and unambiguous.

It shares its 110 kB with the ordinary barrel entry above rather than getting
a looser one, so the two cannot drift apart — both were raised together, in the
same commit, for that reason.

**`bridge-core` is 7.5 kB, not the ~1 kB a contract package sounds like.** It
carries the generated token surface manifest, because `NOT_BRIDGEABLE` has to be
data at runtime for the guard to refuse a clinical write — a bridge writing
`--zb-status-critical` throws, and it can only throw if it knows the list.

**`theme` is 18 kB, and roughly half is zod.** The document schema is what
refuses a malformed theme at the API boundary; hand-rolling that validation to
save the bytes would be a second definition of rules the app and the build
already share, which is the failure mode the whole package exists to avoid.

**The two bridges are ~5 kB each**, excluding the framework they read. That is
the number the architecture's cost claim rests on, and it is measured rather
than estimated — the report that proposed this work guessed ~2 kB.

## host-react's root entry is a structural budget, not a size one

`host-react — the root entry must contain no UI framework` measures **1.39 kB**
against a 2 kB limit, and the headroom is not the point. The package's whole
safety property is that its root entry imports neither antd nor MUI — they sit
behind `./antd` and `./mui` subpath exports, so a consumer resolves a framework
only by mounting one, and the docs site downloads 142 kB or 76 kB on a click
rather than on every page.

`ignore` therefore deliberately lists only `react` and `react-dom`. If a
refactor ever pulled a framework into `index.ts`, this number would go from
1.4 kB to well over a hundred and the budget would fail — which is the same
trick `react — the barrel must contain no UI framework` plays one layer down.
Do not add `antd` or `@mui/material` to its `ignore` list to make a build pass;
that would delete the only thing this entry is measuring.

The two host entries measure the adapter and its bridge, not the framework, on
the same basis as `bridge-antd` and `bridge-mui` above.

## The barrel 118.5 → 121 KB: the smart calendar (15 Oct 2026)

The barrel measured 120.26 KB against 118.5, red on
`feat/date-picker-smart-calendar`. `main` with the same merged dependencies
measures 117.74 KB, so the branch adds 2.52 KB, and all of it is `888eb89`
("quick actions, recommended dates and dates with events") in
`lib/datetime-field.tsx`, `lib/datetime-parts.tsx` and `lib/datetime.ts`:

- **Quick actions.** A toolbar above the grid with one tab stop and arrow-key
  movement, the per-context action sets (`quickActionsFor`), and date actions
  that respect `unavailable`, explicit commit and multiple/range modes.
- **The Recommended view.** A recommendation window listed month by month,
  with collapsible months, its own roving tabstop and a summary line.
- **Recommended days and events on the grid.** Three visual treatments, the
  "why this date" tooltip (placed, flipped and dismissed on Escape, scroll and
  resize), event dots, and accessible names that carry the reason, the checks
  and the events.

No dead code was found to trim: the two unreachable guards that the coverage
gate surfaced were rewritten rather than kept. After that rewrite the barrel
measures 120.13 KB. This is the fourth raise on this entry since 2 Sep, and
per-layer entry points are still the open item recorded above.

## The MUI host 7 → 7.2 kB: the date picker's tokens (15 Oct 2026)

`host-react — the MUI host` measured 7003 B against 7000, red on
`feat/date-picker-smart-calendar` after merging `main`.

All of it is the token surface manifest. The smart-calendar work added twelve
tokens (recommended-day, event-dot and tooltip colours) to
`packages/tokens/src/surface.ts`, and the host reaches that file through
`bridge-core`, which carries the manifest at runtime so a bridge can refuse a
clinical write (see "The bridges" above). Building with `main`'s `surface.ts`
and nothing else changed measures 6.83 kB; restoring the branch's measures
7003 B. The host's own code did not move.

Same reasoning as the theme entry's 130 B for the grid tokens: this is what
themeability costs, not a regression. The antd host carries the same manifest
and still passes at 6.74 kB against 7, so it is left alone.
